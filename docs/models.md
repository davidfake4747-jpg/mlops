# Обучение, MLflow и API

Команды выполняются из корня проекта. Нужны исходные данные и подготовленные
выборки из этапа [Data Ops](data.md). Проверенное окружение — Python 3.13.

## Окружение и обучение

```sh
source .venv/bin/activate
python -m pip install -r requirements-model.txt
dvc repro
```

Если `.venv` ещё нет, сначала выполните `python3 -m venv .venv`.
Файл `requirements-model.lock.txt` фиксирует версии окружения обучения и API;
ограничения этапа данных продолжают действовать через `requirements-data.txt`.

Этап `train` использует только `area`, `rooms`, `floor`, `total_floors`.
Все четыре столбца преобразуются в float с одинаковым порядком в обучении
и инференсе. Адрес, ID, цена, происхождение записи и `cv_fold` не входят в X.

Сравниваются две заранее определённые модели:

- `baseline`: DummyRegressor, медиана обучающих цен;
- `linear`: StandardScaler + LinearRegression, сохранённые единым pipeline.

Для каждого из пяти validation-folds модель обучается заново на остальных
folds. Baseline вычисляет свою медиану только по соответствующей обучающей
части. После кросс-валидации обе модели обучаются на 63 train-объектах
и оцениваются на 15 holdout-объектах. Holdout не используется в fit или подборе
параметров. Это финальная проверка двух фиксированных кандидатов; дальнейшие
подборы по этим же holdout-метрикам сделают оценку оптимистичной.

Регрессия выбирается, если MAE ниже baseline и по кросс-валидации, и на holdout,
а проверенные прогнозы конечны и положительны. Иначе выбирается baseline.
Код обучения дополнительно проверяет отсутствие пересечения ID и адресов
между выборками и единственность validation-fold для каждого дома.

## Результат на предоставленных данных

| Модель | Средняя CV MAE, ₽ | Holdout MAE, ₽ | Holdout MAPE |
| --- | ---: | ---: | ---: |
| Baseline по медиане | 6 960 385 | 6 049 981 | 24,88% |
| Линейная регрессия | 3 192 986 | 2 349 316 | 9,40% |

Выбрана линейная регрессия. Результаты относятся к текущей выборке из
78 квартир и фиксированному разбиению. На 15 holdout-объектах нельзя надёжно
оценить качество на всём рынке Москвы. В `reports/training.json` сохраняются
точные значения, стандартные отклонения CV-метрик и результаты каждого fold.

## Артефакты и воспроизводимость

| Путь | Содержимое |
| --- | --- |
| `models/baseline.joblib` | Baseline, обученный на train |
| `models/linear.joblib` | Обученный pipeline линейной регрессии |
| `models/selected.joblib` | Копия выбранной модели для API |
| `reports/training.json` | Метрики обеих моделей и правило выбора |
| `reports/holdout_predictions.csv` | ID, целевые цены и прогнозы обеих моделей |
| `mlruns/mlflow.db` | Локальная SQLite-база экспериментов |
| `mlruns/artifacts/` | Локальные артефакты MLflow |

Модели и прогнозы версионируются через DVC, отчёт метрик хранится в Git вместе
с `dvc.lock`. Для сохранения новых выходов в настроенное хранилище:

```sh
dvc push
```

При `dvc pull` модели восстанавливаются без повторного обучения.
База MLflow и её собственные артефакты локальные и в DVC не включены.
На другом компьютере они не появятся после Git-клона или `dvc pull`.
Чтобы создать новые записи экспериментов, выполните:

```sh
dvc repro --force train
```

Обычный `dvc repro` пропускает неизменившиеся стадии и не создаёт новые runs.
Метрики и артефакты DVC не содержат случайных run ID или времени запуска.

В MLflow для каждой модели сохраняются параметры estimator/pipeline, seed,
размеры выборок и групп, схема входа, версии зависимостей, SHA коммита,
признак незакоммиченных изменений и DVC-хэш исходных данных. Также сохраняются
метрики, модель в формате MLflow, артефакт API, параметры и отчёты.
Метка `selected` относится к выбору в конкретном запуске, а не глобальному реестру.
Новые модели из MLflow не подменяют модель уже запущенного API автоматически.

## Просмотр MLflow

```sh
mlflow ui --backend-store-uri sqlite:///mlruns/mlflow.db --host 127.0.0.1 --port 5001
```

Откройте http://127.0.0.1:5001 и эксперимент `moscow-housing`.
Порт отличается от порта API, поэтому их можно запускать одновременно.

Справка по API MLflow: [трекинг](https://mlflow.org/docs/latest/ml/tracking/quickstart/)
и [модели scikit-learn](https://mlflow.org/docs/latest/api_reference/python_api/mlflow.sklearn.html).

## Запуск API

Создайте `.env` на основе `.env.example`, заменив `change_me` собственным токеном.
`.env` игнорируется Git. Переменные окружения ОС имеют приоритет над `.env`.

```sh
python service/app.py
# Явный выбор модели:
python service/app.py --model lin_reg
python service/app.py --model baseline_const
```

Форма: http://127.0.0.1:5000. Введите параметры и токен из своего `.env`.
`GET /health` возвращает имя модели и 200, если артефакт загружен;
при отсутствии модели возвращается 503. Для предсказания используйте
`POST /api/numbers`, `Content-Type: application/json` и
`Authorization: Bearer <APP_TOKEN>`.

```json
{"area": 45.5, "rooms": 2, "floor": 3, "total_floors": 9}
```

Успех: JSON с `status: "success"` и целой ценой в рублях в `data`.
Ошибки также возвращаются JSON: 400 для невалидных значений/JSON,
401 для неверного токена, 415 для неподдерживаемого Content-Type,
503 для недоступной модели или недопустимого прогноза. Значения из HTML-формы
в виде числовых строк поддерживаются; NaN, бесконечности, bool, дробные этажи
и комнаты отклоняются. Этаж не может превышать этажность дома.

API использует тот же порядок признаков, что и обучение, и проверяет версию
формата артефакта, scikit-learn и имена признаков estimator. Старые модели
с семью признаками несовместимы. Joblib-артефакты загружать только из
доверенного источника. Сервер запускается локально с выключенным debug.

Проверки:

```sh
python -m pytest -q
dvc status
```
