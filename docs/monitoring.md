# Локальный мониторинг и автоматические проверки

## Подготовка

Нужны Docker и данные/модели из предыдущих этапов:

```sh
source .venv/bin/activate
python -m pip install -r requirements-monitoring.txt
dvc repro
```

Стадия `reference` строит гистограммы `area` и `rooms` только по train.
`reports/reference.json` хранится в Git и содержит агрегаты, DVC-хэш данных
и SHA-256 выбранного артефакта. При смене модели эталон обновляется через DVC.
Holdout, цены, ID и адреса в reference не включены.

В локальном `.env` должны быть `APP_TOKEN` и `GRAFANA_ADMIN_PASSWORD`.
Замените примеры `change_me` собственными значениями. `.env` игнорируется Git
и не попадает в Docker-контекст. При первоначальной настройке этого рабочего
каталога создан `.env` со случайными значениями; существующие пользовательские
настройки не нужно заменять примером.

## Запуск

```sh
docker compose up --build -d --wait
```

| Сервис | Адрес |
| --- | --- |
| Форма API | http://127.0.0.1:5000 |
| Готовность модели | http://127.0.0.1:5000/health |
| Метрики | http://127.0.0.1:5000/metrics |
| Prometheus | http://127.0.0.1:9090 |
| Grafana | http://127.0.0.1:3000/d/housing-api |

В Grafana войдите как `admin`, пароль возьмите из `GRAFANA_ADMIN_PASSWORD`
в `.env`. Дашборд и источник данных создаются автоматически. В форме API
используйте `APP_TOKEN` из того же файла. Все опубликованные порты привязаны
к localhost. Prometheus опрашивает контейнер API каждые 5 секунд.

Модели подключаются в API отдельным томом только для чтения. Образ собирается
без исходных данных, `.env`, истории MLflow и joblib-файлов. Без модели
`/health` возвращает 503; для запуска после Git-клона сначала нужен `dvc pull`
из доступного хранилища или локальное обучение. Само общее хранилище пока
не настроено, используется локальная `.dvcstore` этого компьютера.

Контейнер API работает через Gunicorn с одним worker и четырьмя threads.
Метрики и окно запросов принадлежат одному процессу. Для нескольких worker
или реплик понадобится отдельная схема агрегации; простого увеличения
`--workers` для этой реализации недостаточно.

## Что показывается

- Доступность scrape и готовность модели.
- Частота запросов `/api/numbers`, отдельно доли ошибок 4xx и 5xx.
- p95 задержки запросов, рассчитанный по histogram Prometheus.
- Количество успешных запросов в текущем окне и готовность анализа.
- PSI площади и комнат относительно обучающей выборки.

`/metrics` не включается в счётчики пользовательского HTTP-трафика.
Неизвестные URL объединяются в метку `unmatched`; значения токенов,
URL-параметров, адресов и отдельных признаков не попадают в метки.

Окно сравнения по умолчанию — последние 200 успешных прогнозов. До накопления
30 запросов PSI на дашборде не показывается. Размер окна задаётся через
`DRIFT_WINDOW_SIZE`, минимум — `DRIFT_MIN_SAMPLES`. Ошибки авторизации,
валидации и предсказания не входят в распределение. При перезапуске API
окно сбрасывается. В памяти хранятся только площадь и число комнат;
сырые запросы, токены и адреса не записываются на диск.

Для площади используются квантильные границы train, для комнат — фиксированные
категории 0, 1, 2, 3, 4, 5 и 6+. Сравниваются частоты в бакетах; к каждому
счётчику добавляется 0,5 перед нормализацией. PSI — диагностическая мера
расхождения, не проверка статистической значимости и не метрика точности
модели. Автоматических порогов тревоги пока нет: на 63 train-объектах их
нужно отдельно обосновать. Без фактических новых цен онлайн-MAE не измеряется.
Если reference не соответствует SHA модели, анализ отключается, API продолжает
работать. При отсутствии трафика на графиках rate/p95 могут быть пустые значения.

## Проверка стека

```sh
python scripts/check_stack.py
# Проверка с 30 демонстрационными прогнозами, 400 и 401:
python scripts/check_stack.py --traffic
```

Проверяются готовность API, наличие метрик, успешный scrape Prometheus,
загрузка восьми панелей Grafana и соединение с источником данных.
Демонстрационные запросы меняют текущее окно, поэтому PSI после такого
прогона относится к тестовому потоку.

```sh
docker compose ps
docker compose logs --tail=50 api
docker compose down
```

`down` останавливает сервисы, сохраняя именованные тома истории Prometheus
и настроек Grafana. Очистка томов не требуется для обычного перезапуска.

## GitHub Actions

Workflow `.github/workflows/ci.yml` работает на push, pull request и ручной запуск.
Python 3.13, установка зафиксированных зависимостей, `pip check`, Ruff,
все тесты и проверка конфигурации Compose выполняются в первом job.
После успешных проверок второй job собирает Docker-образ. В CI для проверки
конфигурации используются отдельные фиктивные переменные, секреты не нужны.
Модели и датасет не скачиваются; тесты используют искусственные примеры.
Базовый Python-образ и образы мониторинга закреплены по digest, actions — по SHA.

Это автоматические проверки и сборка. Публикация образа и облачный деплой
не настроены: место размещения ещё не выбрано. Workflow начнёт запускаться
в GitHub после публикации ветки в нашем форке.

Документация: [клиент Prometheus](https://prometheus.github.io/client_python/),
[конфигурация Prometheus](https://prometheus.io/docs/prometheus/latest/configuration/configuration/),
[provisioning Grafana](https://grafana.com/docs/grafana/latest/administration/provisioning/).
